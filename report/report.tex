\section{Repository, Models, and Data}

\textbf{Repository.} \url{https://github.com/usmanbinnaeem/small-model-alignment-starter}. Training code is in
\texttt{smalign/} (batching, log-probabilities, losses) and \texttt{scripts/} (training, generation, judging).
\texttt{submission\_adapter.py} wraps \texttt{smalign}; the 7 public tests and 17 of our own tests pass
(\texttt{tests/}). Every Kaggle notebook is generated by \texttt{kaggle/build\_notebooks.py}.

\textbf{Models.} Base checkpoint \texttt{Qwen/Qwen2.5-0.5B}. Persona task: \texttt{HuggingFaceTB/SmolLM2-360M-Instruct}.

\textbf{Data.} All subsets are built by \texttt{scripts/prepare\_data.py} (seed 42) and listed with counts in
\texttt{data/prepared\_manifest.json}. Only single-turn examples are kept. Sampling shuffles a filtered index list with
\texttt{random.Random(42)}, so the subsets depend only on the source data and the seed.

\textbf{Evaluation sets.} HH DPO: the provided \texttt{eval\_sets/hh\_rlhf\_eval\_300\_seed42.json} (300 prompts, 10
categories). UF DPO: \texttt{eval\_sets/alpaca\_eval\_300\_seed42.json}, built as
\texttt{sorted(random.Random(42).sample(range(805), 300))} over \texttt{tatsu-lab/alpaca\_eval}. Persona: no set was
provided, so we wrote \texttt{eval\_sets/persona\_style\_eval\_40.json} (10 prompts each for cooking, coding, general
help, and safety-sensitive requests; none overlap the training prompts).

\textbf{Prompt format.} One fixed ChatML string for SFT, DPO, and generation:
\begin{center}\footnotesize\ttfamily
<|im\_start|>system\textbackslash nYou are a helpful assistant.<|im\_end|>\textbackslash n<|im\_start|>user\textbackslash n\{instruction\}<|im\_end|>\textbackslash n<|im\_start|>assistant\textbackslash n
\end{center}
followed by the response and the tokenizer's EOS (\texttt{<|endoftext|>}). Prompt and response are tokenized separately
and concatenated, so the response boundary is exact. Prompt and padding labels are $-100$; padding is masked by position
because Qwen uses EOS as PAD. The persona task uses SmolLM2's own chat template, which TRL applies in training.

\textbf{SFT loss reduction.} Mean negative log-likelihood over all unmasked response tokens in a micro-batch; the 16
micro-batch losses are averaged per optimizer step. DPO checkpoint ties on reward accuracy are broken by margin.

\textbf{Generation.} Greedy decoding, \texttt{max\_new\_tokens} 512, \texttt{repetition\_penalty} 1.1, no n-gram block,
stop on \texttt{<|endoftext|>} or \texttt{<|im\_end|>}, fp16, identical for SFT and DPO in each comparison. The persona
comparison uses greedy decoding without a penalty and 256 new tokens, identical across all variants and the base model.

\textbf{SFT} ran 938 steps in 1.3 hours on one T4 (about 1.5k tokens/s). Validation loss stayed flat for the first 300
steps (1.371 at step 0, 1.368 at 300) and then fell steadily as the cosine schedule decayed, to 1.316 at step 938, so the
best checkpoint is the final one. There is no sign of overfitting in one epoch. The small total drop suggests the base
model already models UltraChat-style text well; most of the visible change is behavioral: SFT answers stop on their own
(2 of 300 HH answers hit 512 tokens, against 139 of 300 for the base model) but still fall into list loops under plain
greedy decoding. The fp16 loss scale never dropped below $2^{16}$, so no steps were skipped.

\section{Interpretation and Error Analysis}

\textbf{HH: measured.} DPO beat SFT 139 to 90 with 66 ties. The gains are largest on benign helpfulness (18 to 6),
medical safety (17 to 8), cyber abuse (15 to 5), and harmful instructions (15 to 6); DPO lost on self-harm support (12 to
18) and legal and financial safety (10 to 15). DPO answers are shorter (109 vs 131 words on average).

\textbf{HH: interpretation.} The improvement is real but shallow. Neither model refuses: both list weapons for
``What materials would I need to hurt someone in a fight'' and both explain how to hide malware. Many HH ``chosen''
responses are themselves partial compliance rather than refusals, so DPO learns ``less harmful than the alternative'',
not ``refuse''. Where DPO clearly helps is calibrated caution: asked for a confident yes or no on ignoring sudden one-sided
weakness, SFT says ``Yes, you can ignore'' while DPO advises not to ignore it and to consult a doctor. The self-harm
regression is visible in text: DPO's supportive message becomes awkward (``how much your presence is taking up space in
our lives''). With validation accuracy still rising at the last step, longer training or a larger $\beta$ sweep would be
the next experiments; we did not run them.

\textbf{UF.} \pending{measured result, examples where DPO improves and regresses, interpretation}

\textbf{Persona.} Every variant reached 100\% held-out reward accuracy, yet only some changed what the model says. v1
(LR 5e-5, plain DPO) over-optimised: repetition loops (``You're a mess!'' repeated to the token limit), a factual
regression (it called MD5 password hashing ``secure enough''), and it lost helpfulness 8 to 24. Lowering the LR to 1e-5
(v2, v3) or raising $\beta$ at 2e-5 (v4) kept the model safe and useful but produced near-identical text to the base model,
so style was a tie on all 40 prompts. Adding the SFT term on chosen responses and raising the LR (v5, v6) moved
generation toward the persona while the term kept answers terminated and fluent. Held-out reward accuracy on 20 pairs
therefore did not predict generation behavior; the pairwise judge did. v6 still fails in ways the counts hide: it loops on
some prompts, it lists bleach and ammonia for the toxic-gas prompt (as did v5; the untuned model looped on
``Hugging Face'' instead), and it gives poor first-aid advice for a deep cut. A 360M model trained on 200 stylistic pairs
has little safety knowledge to protect, and greedy decoding amplifies loops.

\section{Limitations and Reproducibility}

\begin{itemize}
\item \textbf{Judge bias.} One judge model. On HH it chose Response A 134 times and B 95 times. Order was randomised
(DPO was A in 151 pairs), and DPO won from both positions (82 to 38 as A, 57 to 52 as B), but the margin is smaller as B.
Shorter answers won more decided pairs (129 vs 98), so a long-answer bias did not favour either model.
\item \textbf{Scale.} One seed per run, 300 prompts per DPO comparison, 40 persona prompts, 20 held-out persona pairs. We
report counts, not confidence intervals.
\item \textbf{Our own persona set.} The 40 persona prompts were written for this report, not provided.
\item \textbf{Failed runs.} The first UF run crashed (OOM) at step 50 and was rerun from step 0 with the fixes above. The
first HH notebook crashed after training and generation in a summary cell; its outputs were complete and are used here.
\item \textbf{Compute.} Kaggle T4 x2, total GPU time \pending{hours}.
\end{itemize}

\textbf{Reproduce.} \texttt{python scripts/prepare\_data.py}, then push the notebooks in \texttt{kaggle/} in order
(\texttt{01\_sft}, \texttt{02\_dpo\_hh}, \texttt{03\_dpo\_uf}, \texttt{04\_lora}); each restores its previous output
and resumes training if rerun. Judge with \texttt{scripts/judge\_pairwise\_kaggle.py} and rebuild all tables with
\texttt{scripts/summarize\_results.py}. Configs: \texttt{configs/}. Metrics, curves, and summaries:
\texttt{results/\{sft,dpo\_hh,dpo\_uf\}/}. Generations: \texttt{results/eval\_generations/},
\texttt{results/baseline/}, \texttt{results/persona/generations/}. Pairs and judgments: \texttt{results/judgments/},
\texttt{results/persona/judgments/}.
